# Run Instructions

## 1. What this is

ID Express is a Flutter + Firebase app for national ID services: applicants
register, submit a four-step ID application, upload documents and book an
appointment; officers and supervisors review and approve or reject; admins
assign roles. There is no backend server: the app talks to Firebase directly,
and `firestore.rules` / `storage.rules` enforce access.

| Part | Folder | Stack |
| --- | --- | --- |
| Flutter client (Android, iOS, web; macOS, Windows, Linux runners) | `lib/`, platform folders | Flutter, Dart `^3.10.4`, Riverpod 3, go_router 17 |
| Firebase rules and indexes | `firestore.rules`, `storage.rules`, `firestore.indexes.json`, `firebase.json` | Firebase CLI |
| Release scripts | `scripts/` | Dart command-line scripts |

## 3. Credentials and configuration

The app reads no environment variables and has no `.env` file. All
configuration is Firebase client configuration, currently pointing at the
original owner's Firebase project. The `AIza...` keys in these files are
Firebase client identifiers, which are public by design; replace them by
pointing the app at your own project.

| Placeholder | File(s) | What it is | Where to get your own |
| --- | --- | --- | --- |
| `<provide-your-own-firebase-project-id>` | `.firebaserc`, `firebase.json` (`flutter` block), `lib/firebase_options.dart` | Firebase project ID | Firebase console, new project |
| `<provide-your-own-firebase-options>` | `lib/firebase_options.dart` | API key, app ID, sender ID, bucket per platform | Generated by `flutterfire configure` |
| `<provide-your-own-google-services-json>` | `android/app/google-services.json` | Android Firebase config | Generated by `flutterfire configure`, or Firebase console > Project settings > Android app |
| `<provide-your-own-googleservice-info-plist>` | `ios/Runner/GoogleService-Info.plist` | iOS Firebase config | Generated by `flutterfire configure`, or Firebase console > iOS app |
| `<provide-your-own-apple-team>` | `ios/Runner.xcodeproj/project.pbxproj` (`DEVELOPMENT_TEAM`) | Apple signing team | Xcode > Runner > Signing & Capabilities |
| `<provide-your-own-application-id>` | `android/app/build.gradle.kts` (`applicationId`, `namespace`), iOS/macOS `PRODUCT_BUNDLE_IDENTIFIER` | App identifiers (currently `com.example...`) | Choose your own; re-run `flutterfire configure` afterwards |
| `<provide-your-own-android-release-signing>` | `android/app/build.gradle.kts` (`buildTypes.release`) | Release keystore (currently the debug key) | `keytool`, see Android docs |
| `<provide-your-own-apns-key>` | Firebase console only | APNs auth key for iOS push | Apple Developer > Keys |

Setup steps:

1. Create a Firebase project. Enable **Authentication > Email/Password**,
   **Cloud Firestore**, **Cloud Storage** and, if wanted, **Cloud Messaging**.
2. `firebase login`, then `firebase use --add` and pick your project (rewrites
   `.firebaserc`).
3. `flutterfire configure` from the repository root, selecting your project and
   the platforms you need. Generated (do not hand-edit):
   `lib/firebase_options.dart`, `android/app/google-services.json`,
   `ios/Runner/GoogleService-Info.plist`, `firebase.json` `flutter` block.
   For macOS and Linux the committed options are `YOUR_...` placeholders, so
   include those platforms here if you need them.
4. Deploy rules and indexes (paths come from `firebase.json`; `storage.rules`
   is not referenced there, so deploy it by adding a `"storage": {"rules":
   "storage.rules"}` entry or by pasting it into the console):

   ```bash
   firebase deploy --only firestore:rules,firestore:indexes
   ```

5. Hand-edit only the signing team, application IDs and release signing listed
   above.
6. Run the app, register a user, then in the Firestore console set
   `users/{uid}.role` to `admin` (the rules stop users promoting themselves).
   Admins can then assign `officer` / `supervisor` in the app.
7. **Confirm it worked:** registration creates `users/{uid}` with
   `role: "applicant"` in your project; an admin sees the "Manage Users" icon on
   the officer dashboard; an uploaded document appears under `documents/{uid}/`
   in Storage.

## 4. Build, run and test

All commands run from the repository root.

```bash
flutter pub get
```

Generated `*.g.dart` files are committed. Regenerate only after editing an
annotated provider or model:

```bash
dart run build_runner build --delete-conflicting-outputs
```

### Android

```bash
flutter run -d <android-device-id>
flutter build apk --debug
flutter build apk --release --split-per-abi
```

### iOS

```bash
open ios/Runner.xcworkspace          # set your signing team once
flutter run -d <ios-device-id>
flutter build ios --debug --no-codesign
flutter build ipa --release
```

### Web

```bash
flutter run -d chrome                # Flutter picks a free localhost port and prints it
flutter build web                    # output in build/web
```

Document upload does not work on web (it uses `dart:io`), see
`docs/KNOWN_ISSUES.md`.

### Desktop

```bash
flutter run -d macos | windows | linux
```

Requires the corresponding Firebase options from step 3.

### Tests and analysis

```bash
flutter analyze
flutter test
```

Expected as of 2026-11-18: analyze clean; 2 tests, 1 pass, 1 known failure in
`test/model_test.dart`.

## 5. Quick start

1. `git clone` the repository and `cd` into it.
2. `flutter pub get`
3. `flutterfire configure` (your Firebase project, Android/iOS/web).
4. `firebase deploy --only firestore:rules,firestore:indexes`
5. `flutter run -d chrome` (or an Android/iOS device).
6. Register, then promote yourself to `admin` in the Firestore console.

## 6. Deployment

- **Test builds:** `dart scripts/deploy_testing.dart --build` bumps the version
  (`scripts/bump_version.dart`, also updates `web/version.txt`), runs
  `flutter build ipa --release` and `flutter build apk --release
  --split-per-abi`, uploads to AppSend (no API key, 150 MB cap) and prints
  install links. Options: `--no-bump`, `--ios-only`, `--android-only`,
  `--testers=...` (max 5), `--message=...`. Details in `scripts/README.md`.
- **Version only:** `dart scripts/bump_version.dart`.
- **Web hosting:** `firebase.json` defines Hosting with `"source": "."`
  (Firebase CLI framework-aware hosting), an SPA rewrite to `/index.html`, and
  cache headers. Deploy with `firebase deploy --only hosting`; the CLI's web
  frameworks support may need `firebase experiments:enable webframeworks`.
  Bump `web/version.txt` on each release so the loader in `web/index.html`
  clears stale caches.
- No CI workflows are present in the repository.

## 7. Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `[cloud_firestore/permission-denied]` on every read | Rules not deployed to your project, or user has no `users/{uid}` document | Deploy `firestore.rules`; register through the app so the profile is created |
| `FAILED_PRECONDITION: The query requires an index` | Indexes not deployed | `firebase deploy --only firestore:indexes` and wait for the build to finish |
| Officer screens never appear after login | User role is `applicant` | Set `role` to `officer`/`supervisor`/`admin` in the console, or via an admin in the app |
| `flutter pub get` changes `pubspec.lock` and `analysis_options.yaml` | Newer Flutter SDK pins different SDK packages and adds an analyzer exclude block | Expected; review and keep or discard the change |
| `flutter.sdk not set in local.properties` | Android project opened before Flutter generated it | Run `flutter pub get` or any `flutter build apk` once |
| Android warning about plugins applying the Kotlin Gradle Plugin | Plugin compatibility with Flutter's built-in Kotlin | Warning only today; update plugins when compatible versions exist |
| iOS build fails with signing errors | `DEVELOPMENT_TEAM` belongs to the original owner | Select your own team in Xcode |
| Firebase fails on macOS or Linux | Options are placeholders; macOS sandbox lacks `network.client` | Run `flutterfire configure` for those platforms and add the entitlement |
| Upload fails on web | `dart:io` `File` used for upload | Use a mobile build |
| Upload fails with `unauthorized` | `storage.rules` not deployed, or file over 20 MB | Deploy the Storage rules; use a smaller image |
