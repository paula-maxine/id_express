## Firebase reconstruction

The Firebase client configuration files were kept so the project still compiles
as delivered. They are client identifiers, not credentials: anyone can read
them from a shipped app, and access is governed by `firestore.rules` and
`storage.rules`. A buyer must still point the app at their own project:

1. Create a Firebase project; enable Authentication (Email/Password),
   Cloud Firestore, Cloud Storage and (optionally) Cloud Messaging.
2. Install the Firebase CLI and FlutterFire CLI, then run `firebase login` and
   `firebase use --add` (updates `.firebaserc`).
3. From the repository root run `flutterfire configure`, selecting Android,
   iOS, web and any desktop platforms. This rewrites
   `lib/firebase_options.dart`, `android/app/google-services.json`,
   `ios/Runner/GoogleService-Info.plist` and the `flutter` block of
   `firebase.json`.
4. Deploy rules and indexes:
   `firebase deploy --only firestore:rules,firestore:indexes`. `storage.rules`
   is not referenced from `firebase.json`; publish it in the Firebase console
   (Storage > Rules) or add a `"storage": {"rules": "storage.rules"}` entry and
   run `firebase deploy --only storage`.
5. Run the app, register a user, then set that user's `role` to `admin` in the
   Firestore console.
6. **Verify:** registering creates `users/{uid}` with `role: applicant` in your
   project; submitting an application creates an `applications` document;
   uploading a document creates an object under `documents/{uid}/` in Storage.
